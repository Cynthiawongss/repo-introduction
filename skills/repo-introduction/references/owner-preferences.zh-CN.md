# 本仓库主人的默认偏好

来自 2026 年 11 月的几次项目协作（五个 Skill 仓库、ringcay）。新任务以这些为起点，当前明确指令优先；不要把它们当成所有用户的规定。

## 沟通与节奏

- 用中文沟通。项目介绍英文为主页 `README.md`，中文单独 `README.zh-CN.md`，两边顶部互相切换。
- 已授权的可逆工作直接做，不反复问"要不要开始"。需要选图时留出判断空间；说"先看内容"就先做内容。
- 每次汇报说清：改了什么、核对了什么、没核对什么、有没有提交、有没有推送。
- 要求"新建 GitHub 仓库再上传"时，就新建仓库，不往已有仓库里塞。

## 文案

- 保留已认可的名字；用真实用户问题和具体结果讲价值；适量表格，避免长列表堆叠。
- 不写助手署名、聊天过程、制作花絮。依赖、限制、验证范围要保留。
- 例子不默认用教育、小孩、学习者场景。
- 情感类产品要写出人和人的关系（情侣、朋友），不只写功能。

## 视觉

- 横版 16:9，有编辑设计感，Pinterest／Instagram 的成熟感。喜欢：符号艺术、像素／ASCII、细线、颗粒、摄影拼贴、手写注释、适当留白。3D 可以，但不是必选。
- 温馨、有生活感、明亮自然；拒绝灰黄沉闷、"灰灰的"、多巴胺不够。
- 拒绝过度可爱：卡通玩偶、幼态 IP、儿童绘本感、糖果色、夸张爱心；也拒绝无必要的手部主体。
- 主体要有细节和设计感。素圈、素面会被说"太素""很 low"；宝石、刻纹、珠边这类真实工艺细节更受认可。
- 图必须贴题。好看但不贴题（鞋子拼贴）会被换掉；保留喜欢的风格维度，只换主体。
- 每个项目的隐喻、构图、配色要不同，不要都套粉蓝紫，也不要都套荧光黄绿。
- 曾认可的方向（仅作参考，不是默认）：Rebel by Design 式颗粒照片、错位印刷、局部荧光、杂志拼贴；ringcay 的"用产品自己的 3D 代码渲染 + 手写注释 + 拍立得 + 引线"。
- 一个项目一个项目选图，每次说清项目名和候选编号；当前项目没选定，不跳到下一个。

## 图怎么做

- 优先用项目自己的代码渲染或用真实素材排版合成；AI 生图只用来画代码画不了的东西，用付费额度前先问。
- 截图必须是真实运行的产品、动画结束后的完成状态、虚构示例数据。
- 概念插图要在图下注明"概念插图，不是产品截图"。
